## 3. 相对 1.0.0 的兼容性

**本版含破坏性变更。** 相对 v1.0.0 对外仓头文件，公开 C 符号**新增 9 个、删除 4 个**（v1.0.0 头文件 31 个 `XG_API` 函数声明，本版 36 个；两份头文件的 `XG_API` 声明逐个 `diff` 核对，结果与本节清单一致）。

- 删除的 4 个符号：`xg_subscribe_cloud`、`xg_unsubscribe_cloud`、`xg_subscribe_raw_cloud`、`xg_unsubscribe_raw_cloud`，及对应的 C++ 方法。**不保留兼容**。
- `SOVERSION` 由 `1` 改为 `1.1`，SONAME 由 `liblixel_sdk.so.1` 改为 `liblixel_sdk.so.1.1`（SONAME 两位规则见 [README.md](../../README.md)）。按 1.0.0 编译的程序，`NEEDED` 为 `liblixel_sdk.so.1`，不会自动加载 1.1.0 库；使用了被删符号的程序必须改用新接口并重新编译。
- 设备端同步删除旧 key（`reloc_device_cloud`、`raw_pointcloud`、`device_reloc_cloud`），不双发。**必须配套升级设备固件**，见 §6。
- `device_reloc_cloud` 及其订阅接口 `xg_subscribe_device_reloc_cloud` / `xg_unsubscribe_device_reloc_cloud`（C++ `subscribeDeviceRelocCloud`）在本版内先新增后删除，对 1.0.0 用户的净效果是：旧 `subscribeCloud`（key `reloc_device_cloud`）的替代入口改为 `subscribeDeviceUndistCloud`（key `device_undist_cloud`），见 §4 Changed 第 3 条。

这与 1.0.0 起“公开符号只追加不删改”的承诺不一致，是经决策后的有意破坏。

## 4. 变更清单

### Removed（破坏性）

| 删除的接口 | 替代 |
|-----------|------|
| `xg_subscribe_cloud` / `xg_unsubscribe_cloud`（C++ `subscribeCloud`），key `reloc_device_cloud` | `xg_subscribe_device_undist_cloud` / `xg_unsubscribe_device_undist_cloud`（C++ `subscribeDeviceUndistCloud`），key `device_undist_cloud`；内容为 Locate 去畸变点云，见 §4 Changed 第 3 条 |
| `xg_subscribe_raw_cloud` / `xg_unsubscribe_raw_cloud`（C++ `subscribeRawCloud`），key `raw_pointcloud` | `xg_subscribe_device_undist_cloud` / `xg_unsubscribe_device_undist_cloud`（C++ `subscribeDeviceUndistCloud`），key `device_undist_cloud`；**内容与旧 `subscribeRawCloud` 不同**，见 §4 Changed 第 3 条 |

### Changed

1. **点云命名修正。** 旧 `subscribeRawCloud` 容易被理解为“雷达原始点”，实际是 SLAM 运动去畸变后的单帧扫描、设备（IMU）系、上游 1/4 降采样，**不是雷达全量点**。1.1.0 改名为 `subscribeDeviceUndistCloud`，说明书同步更正。
2. **预编译示例的目录布局改为 `bin/<arch>/<分类>/<名>`**（分类即 `examples/` 的子目录名）。例如 1.0.0 的 `bin/x86_64/record_demo` 在 1.1.0 是 `bin/x86_64/record/record_demo`。二进制内嵌的 rpath 已按新层级重算，保持 `bin/<arch>` 与 `lib/<arch>` 的相对位置不变即可直接运行。依赖旧路径的脚本需要修改。
3. **`device_undist_cloud` 语义变更（需设备固件配套）。** 参见 [`robot_sdk_c.h`](../../include/xg/robot_sdk_c.h) 中 `xg_subscribe_device_undist_cloud` 注释。

   | 项 | 旧语义（固件发布 `device_undist_cloud` 的旧版） | 新语义 |
   |----|------------------------------------------------|--------|
   | 内容来源 | SLAM 运动去畸变后的单帧，上游 1/4 降采样 | Locate 输出的去畸变点云（`imu_cloud`） |
   | 坐标系 | 设备（IMU）系 | 设备（IMU）系 |
   | 时间戳 | 该帧 SLAM 输出时间戳（秒） | 该帧 Locate 输出时间戳（`UndistortCloudType.timestamp`，秒） |
   | 单帧点数 | 基线 | 取决于 Locate 输入点云（当前为驱动层 1/4 降采样，未验证）；全量输入属 locate-full-cloud-feed（RFC 状态：提案，未实现） |
   | 建图阶段 | 有数据 | **无数据（断流）**：Locate 未输出时该 key 不发布；订阅仍返回 `XG_OK`。设备端 Locate 只在 `setLocInitPose` 之后才启动，只录制、不注入初值时，该 key 和 `device_locate`（`xg_subscribe_pose`）都没有数据 |

   影响：
   - **回调耗时。** 回调运行在 Zenoh 会话接收线程，阻塞会拖住本进程全部订阅。SDK 回调耗时**未测量**。回调单次耗时上限：待定（ms）。回调内禁止同步文件 IO、`join`、`startLocate` 等阻塞操作，只做拷贝或入队。
   - **带宽。** 链路带宽余量**未测量**。
   - **订阅方式不变。** 接口名、签名、`xg_cloud_frame_t` 布局均不变；变化的只是数据内容与点数。
   - **与 `device_raw_cloud` 的区别不变。** `device_raw_cloud` 仍是雷达全量原始点云，不做运动去畸变，每点带 `time_offset_us` 与 `ring`；`device_undist_cloud` 是 Locate 输出，无逐点时间与线束号。

### Added（新增 9 个公开 C 符号）

| 能力 | C 接口 | C++ 方法 | key | 说明 |
|------|--------|----------|-----|------|
| Locate 去畸变点云 | `xg_subscribe_device_undist_cloud` / `xg_unsubscribe_device_undist_cloud` | `subscribeDeviceUndistCloud` | `device_undist_cloud` | 设备（IMU）系，量级 ~10 Hz（未实测）。内容为 Locate 输出的去畸变点云，点数取决于 Locate 输入（未验证）；建图阶段无数据。语义细节见 §4 Changed 第 3 条 |
| **原始雷达点云（全量）** | `xg_subscribe_device_raw_cloud` / `xg_unsubscribe_device_raw_cloud` | `subscribeDeviceRawCloud` | `device_raw_cloud` | 设备（IMU）系，~10 Hz。一次完整扫描的全部点，不降采样、不做运动去畸变，每点带 `time_offset_us` 与 `ring`。帧时间戳取自雷达自身时钟，不保证等于设备系统时钟（见 [api_reference_v2.md §0.8](../api_reference_v2.md#08-时间戳时基与换算)）。新类型 `xg_raw_point_t`（固定 24 字节）、`xg_raw_cloud_frame_t`。**仅 RoboSense 雷达设备发布** |
| 深度图 | `xg_subscribe_depth` / `xg_unsubscribe_depth` | `subscribeDepth` | `depth/center` | 中间相机 AI 推理产出的度量深度，单位 m，行优先 float。**设备端默认配置下不发布此 key**：`lixel_t1xb.camera_center.ai.fps` 默认为 0，设备把该项配置为大于 0 且 AI 模型就绪后才有数据；无数据时订阅仍返回 `Ok`。详见 §6 第 4 条 |
| 设备网络配置 | `xg_set_device_network`、`xg_confirm_device_network` | `setNetwork`、`confirmNetwork` | — | 修改设备对外网口 IP 与网段，须在确认窗口内重新连接并确认，否则设备自动回滚。`prefix_len` 取值 8 到 30，确认窗口 10 到 120 秒（默认 60 秒） |
| 设备时间（只读） | `xg_get_device_time` | `getDeviceTime` | —（复用 `getDeviceStatus` 命令，应答 `data` 里追加 `time`） | 查询设备系统时钟（Unix epoch 微秒）和时区偏移，并给出与本机时钟的偏差区间（宽度等于往返时延）。新结构 `xg_device_time_t`（48 字节）。**只读，SDK 不提供设置设备时间的能力。** 各订阅数据的时间戳取自哪个时钟、如何换算见 [api_reference_v2.md §0.8](../api_reference_v2.md#08-时间戳时基与换算) |

另新增版本宏 `XG_SDK_VERSION_STRING`、`XG_SDK_VERSION_NUMBER`（1.0.0 头文件只有 `XG_SDK_VERSION_MAJOR` / `MINOR` / `PATCH`）。

### ROS2 桥接（`ros2/`）

ROS2 桥接随 1.1.0 一并发布，包名由 `lixel_sdk_ros2` 改为 `lixel_ros`，是对 1.0.0 `ros2/` 的**破坏性变更**，已有的 launch、脚本和下游订阅需要同步修改：

- 包名 `lixel_ros`；新增启动脚本 `ros2/start_lixel_ros.sh`、相机 JPEG 解码节点 `ros2/scripts/jpeg_decoder_node.py`（发布 `image_raw`）和坐标系示意图 `ros2/images/`。
- 节点只订阅数据，**不再自动启停录制**；先用 SDK 完成初始化、设置初始位姿、`startRecord()`，再启动桥接。
- 话题与 TF：`/odom`（`map → base_link`，已叠加外参）、`/tf`（`map → imu_link`）、`/tf_static`（`imu_link → base_link`）；原 `/lixel/odom`、`/lixel/tf` 不再发布。
- 点云：删除 `/lixel/cloud_points`（重定位点云）与 `/lixel/raw_cloud`，新增 `/lixel/device_undist_cloud`（订阅 `subscribeDeviceUndistCloud`）。
- 外参：`lidar_to_base_*` 参数，旋转固定、平移默认 0；全部参数从参数文件读，命令行 `device_ip:=` 可单独覆盖。
- 所有话题 `header.stamp` 改用本机 ROS 时钟。
- 详见 [`ros2/README.md`](../../ros2/README.md)。

### Fixed

- 去畸变点云频率描述：1.0.0 文档对 Locate 点云写 ~1 Hz，按设备端注释更正为量级 ~10 Hz（未实测）。

## 5. 行为与安全

- SDK 层没有身份认证。`xg_set_device_network` 与录制启停走同一连接，能连上设备的主机都能调用；须独立 VLAN、同网段直连。
- `xg_set_device_network` 同步阻塞，同一句柄不可重入；返回 `XG_OK` 之后只允许对该句柄调用 `xg_device_close()`，确认须用重新打开的句柄。设备应用进程重启后，“已确认 / 已回滚”的记录丢失，`xg_confirm_device_network` 一律返回 `XG_ERR_REJECTED`。
- `xg_raw_cloud_frame_t.points` 指向 SDK 内部线程本地缓冲，**仅回调期间有效**，下一帧覆盖同一块内存；需保留须在回调内深拷贝。单帧点数多，回调内只做拷贝或入队，阻塞会拖住本进程全部订阅。
- 原始点云坐标在设备端四舍五入到 1 mm，最大误差 0.5 mm。
- 其余约束（启停异步、同一句柄不可重入、回调在 SDK 内部线程）同 1.0.0。

## 6. Known Limitations

1. **依赖设备端固件。** 须把设备固件升级到提供 `device_undist_cloud` 与 `getDeviceStatus` 应答里 `time` 字段的新版；旧固件不带这两项。`getDeviceTime` 需要固件在 `getDeviceStatus` 应答里带 `time`；旧固件返回 `Protocol`，旧 SDK（1.0.0）连接新固件不受影响。订阅方面，1.1.0 订阅的 key 是 `device_undist_cloud`、`device_raw_cloud`、`depth/center`。1.1.0 SDK 连接不发布这些 key 的旧固件，订阅仍返回 `Ok` 但收不到对应数据；1.0.0 SDK 连接新固件同样收不到点云。
2. **`device_undist_cloud` 与位姿在建图阶段无数据，且点数与回调耗时影响未实测。** 设备端 Locate 的时序是录制启动时初始化、`setLocInitPose` 喂入初值并启动算法；只录制、不调用 `setLocInitPose` 时 Locate 不启动，`pose_demo`、`undist_cloud_demo`、`subscribe_demo` 收不到位姿和去畸变点云（板端实测），出数据请注入初值：`pose_demo`、`undist_cloud_demo`、`subscribe_demo` 现已自带注入（命令行末尾可选 `[X] [Y] [Z]`），也可按 `reloc_demo` 的流程。订阅返回 `Ok` 但 Locate 未输出时没有回调；新旧固件内容语义不同（旧固件为 SLAM 单帧，新固件为 Locate 输出），SDK 无法从帧里区分，须由集成方按所连设备的固件情况判断。SDK 回调耗时与链路带宽均未测量，回调耗时上限待定。
3. **`device_raw_cloud` 订阅返回 `Ok` 也可能没有数据**，SDK 无法区分原因：设备雷达不是 RoboSense；设备端外参文件 `extrinsic_imu_lidar.yaml` 缺失或不是合法刚体变换（设备丢弃该帧）；设备拥塞丢帧（本路 `seq` 取设备雷达 `frame_id`，可用其跳变发现）；设备尚未进入录制 / 扫描状态。订阅后到收到首帧的延迟未测量。
4. **深度图需要设备开启 AI 推理，且当前只有中间相机有数据；默认配置下设备不发布 `depth/center`。** 新版设备固件把 T1XB 配置文件 `modeling_app_t1xb.yaml` 的 `lixel_t1xb.camera_center.ai.fps` 由 10 改为 0（注释为 AI 专用 RGB 输出流帧率）。设备端只在 `ai.fps > 0` 时创建 AI 专用 RGB 输出流，AI 帧回调只挂在这条输出流上，`ai.fps` 为 0 时没有深度推理的输入帧。要有 `depth/center` 数据，须由设备端把该项配置为大于 0（配置文件注释要求整除相机 `fps`）并保证 AI 模型加载成功。订阅在无数据时仍返回 `Ok`，SDK 无法区分。仅 T1XB 配置文件含 `ai` 段，其余机型配置文件没有该键。
5. **时间戳不在同一个时钟上。** 图像取自设备系统时钟，深度图沿用图像时间戳（推断）；IMU 随平台取 MCU 或雷达时钟；位姿与点云的时基未在设备代码中确认。`getDeviceTime` 的偏差区间只对图像及沿用其时间戳的深度图成立，不能替代设备侧的时间同步。依据是固件源码静态阅读，未上板实测。详见 [api_reference_v2.md §0.8](../api_reference_v2.md#08-时间戳时基与换算)。
6. **说明书缺口。** [api_reference_v2.md](../api_reference_v2.md) 的深度图只有数据可用性说明（§7 开头列表），设备网络配置、地图管理（`xg_upload_map` / `xg_set_active_map` / `xg_list_maps` / `xg_delete_map`）的条目，这些接口的定义以头文件注释为准。

## 7. 升级注意（自 1.0.0）

1. 同步替换**全部头文件**与 `liblixel_sdk.so`，禁止混用。SONAME 变为 `liblixel_sdk.so.1.1`，用 1.0.0 编译的程序须重新编译（按 `liblixel_sdk.so.1` 链接的旧程序不会加载新库）；`lib/<arch>/` 里不再有 `liblixel_sdk.so.1`，清理旧副本后再部署。
2. 全文搜索 `subscribeCloud`、`subscribeRawCloud`、`xg_subscribe_cloud`、`xg_subscribe_raw_cloud` 及对应取消订阅接口，换成上表中的新接口并重新编译。注意：两者的替代接口都是 `subscribeDeviceUndistCloud`，其内容是 Locate 去畸变点云（见 §4 Changed 第 3 条），不是旧 `subscribeRawCloud` 的 SLAM 单帧；点数、回调耗时与建图阶段断流都会变化，回调内只做拷贝或入队。
3. **先把设备固件升级到配套新版**，否则点云订阅 0 帧。
